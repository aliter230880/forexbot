## Стратегия 1: Сетка (grid_engine.py, PROFILE=STANDARD)

**Результат демо: +$503.79 за 4 дня, 35 закрытых пар.** Лучший PnL, но стартовал раньше остальных.

| Параметр | Значение |
|----------|----------|
| Инструмент | XAUUSD.s (золото) |
| Сетка | 15 buy-limit уровней ниже цены, шаг $4 |
| Лот | 0.02 (контракт 100 oz, маржа ~$18/уровень при 1:500) |
| Тейк пары | **серверный TP позиции** (TRADE_ACTION_SLTP) — работает при выключенном боте |

### Авто-механизмы
1. **Авто-сдвиг вверх** — цена > верх сетки + 1 шаг → пересборка вокруг цены (кулдаун 10 мин)
2. **Поддержание снизу** — сработал уровень → добавляется новый ниже нижнего
3. **Ремонт TP** — сбит/отсутствует TP → переустановка; если bid ≥ TP → закрытие по рынку
4. **Тренд-фильтр** — ≤ -3%/24ч (H1) → отмена buy и пауза; возврат при > -2%
5. **Margin guard** — стоп при -12% equity от watermark; margin level < 300% → закрыть худшую; -5%/день → стоп до след. дня
6. **Weekend flat** — пятница **23:00 UTC** всё закрыть (рынок PU Prime до 23:55); сброс по широкому окну рыночного времени (не привязан к моменту открытия)
7. **Аномалия-защита** — SELL-позиции с magic бота закрываются

### Пресет MICRO (PROFILE=MICRO) — для депозитов $100-150
5 уровней · шаг/TP $8 · лот 0.01 · тренд-пауза -2% · стоп сетки -15% · дневной лимит -5%.

Откат к EMA9 внутри тренда + RSI в рабочей зоне (45-72 лонг / 28-55 шорт).

## Стратегия 4: Мульти-символьный бот (multi_engine.py) — АКТИВЕН

Отдельный процесс, свой magic (`MULTI_MAGIC=20260825`), своё состояние

Логика входа идентична scalp v2, но применяется параллельно к нескольким инструментам:
частота набирается диверсификацией, а не ослаблением фильтров.

### Отбор инструментов (скан всех символов брокера, 2026-08-25)
Критерии: стоп на мин. лоте ≤ 2.5% от $100 **и** спред ≤ 30% от ATR(M5).

**Прошли (6):** NAS100.s, GER40.s, UK100.s, USOUSD.s (нефть), UKOUSD.s, BTCUSD — стоп $0.07–2.43 (0.1–2.4% от $100).

**Отсеяны:**
| Инструмент | Причина |
|---|---|
| XAUUSD, XAGUSD | стоп 4.8% / 6.1% от $100 при мин. лоте — дорого для микросчёта |
| EURUSD, GBPUSD, AUDUSD | спред съедает 65–100% ATR(M5) — **опровергло прежнюю гипотезу «мажоры лучше для мини-баланса»** |
| SOLUSD, XRPUSD, LTCUSD, ETHUSD | спред 180–750% от ATR |
| HK50, EU50, FRA40 | спред 37–52% от ATR |

### Параметры
Лот 0.01 · макс. 3 позиции всего и 1 на инструмент · 45 сделок/день суммарно ·
кулдаун 3 мин на символ · окно 07:00–19:00 UTC · серия 3 стопов → пауза инструмента до след. дня.

**Риск-фильтр (постоянный):** перед входом считается стоимость стопа; если > 2.5% от
тестовой базы $100 — сделка пропускается, причина видна в админке. Защита от скачков волатильности.
Дневной лимит убытка считается от **тестовой базы $100**, а не от демо-счёта.

**Статус (27.08):** 32 закрытых сделки, WR 25%, **−$3.16** — медленно спускает на спреде.

### Что осталось (блокеры и очередь)

**Блокер 1 — ПОРТЫ (REG.RU).** Входящие 80/443/8181 дропаются на границе REG.RU:

Тикет в поддержку REG.RU открыт (юзер). В панели ЛК раздел портов не найден.
После открытия: `C:\caddy\caddy.exe run --config C:\caddy\Caddyfile` (скачан,
Caddyfile на оба домена готов) → https://fxbot.space + admin.fxbot.space с
авто-HTTPS Let's Encrypt. План Б при затягивании: Cloudflare Tunnel (cloudflared).

**Блокер 2 — TELEGRAM 409.** api.telegram.org с RU IP заблокирован РКН
(`TG_API:000` с VPS при работающем с локалки через VPN). **Патч перенесён из
крипто-бота (trade):** `_pin_telegram_dns()` в `notifier.py` + `TELEGRAM_API_IPS`
в `config.py`/`.env` (пиннинг живых IP 149.154.167.220 / .175.50 / .166.110,
SNI валидный). Задеплоено на сервер, процесс перезапущен — в логе
«telegram DNS pinned», ручной `getMe` через IP → `{"ok":true}` (транспорт работает).
НО поллинг ловит **HTTP 409 Conflict** — где-то ещё есть второй consumer getUpdates
того же токена. Проверено: локальная машина чиста (процессов/задач нет), вебхук
не установлен (`getWebhookInfo` → url:"", pending_update_count=4). Главный
кандидат — крипто-бот (aliter230880/trade) на другом VPS с тем же токеном.
**Следующий шаг (разбор остановлен по указанию юзера):** найти второй поллер
или выпустить новый токен бота и заменить в `.env` VPS.

**Очередь после блокеров:** старт Caddy → HTTPS; копитрейдинг dry-run на VPS

## Копитрейдинг — ГОТОВ, dry-run пройден, СЛЕДУЮЩИЙ ШАГ: сервер заказчика

Файлы: **`copier_engine.py`** (движок) + **`main_copier.py`** (раннер run/status) +
таблица **`copy_trades`** в bot.db + состояние `data/state_copier.json`.

**Архитектура:** мастера (гибрид и др.) пишут сделки в общую bot.db → копир-процесс
читает их и зеркалит на ВТОРОМ терминале MT5 (счёт подписчика). Ни один мастер
не знает о копире — отвязка полная. При переносе на сервер заказчика мастера и
копир живут на одной машине — общая bot.db, без сетевого доступа.

| Механика | Реализация |
|---|---|
| Лот | баланс_подписчика / баланс_мастера × лот_мастера → нормализация к шагу, потолок MAX_LOT; COPIER_FIXED_LOT>0 — фикс. лот без масштабирования |
| Вход | рыночный при появлении сделки мастера; SL/TP переносятся от мастера (уровни абсолютные), раздвигаются до мин. дистанции stops_level + 1.5 спреда |
| Закрытие | мастер закрылся (tp/sl/manual) → копир закрывает зеркалку по рынку, pnl обеих сторон пишется в copy_trades |
| Свежесть | копируются сделки не старше 300 сек; на первом старте last_master_id = MAX(id) — накопленную историю не копируем |
| Лимиты | макс. зеркалок одновременно (6), макс. лот (0.1), повторное зеркалирование того же тикета исключено (already_copied) |
| Filling | фолбэк IOC → FOK → RETURN (как у остальных ботов) |

**Конфиг (всё в .env, дефолты в config.py):**

| Переменная | Дефолт | Смысл |
|---|---|---|
| COPIER_DRY_RUN | 1 | 1 = только логи и БД, ордера НЕ отправляются |
| COPIER_MASTERS | hybrid,kiro | версии-мастера из scalp_trades |
| COPIER_LOGIN / PASSWORD / SERVER | 0 / — / — | счёт подписчика (0 = текущий счёт терминала) |
| COPIER_MT5_PATH | E:\AI\MetaTrader5\terminal64.exe | путь ко 2-му терминалу |
| COPIER_MASTER_BALANCE | 100000 | база для масштабирования лота = баланс мастера |
| COPIER_FIXED_LOT / COPIER_MAX_LOT | 0 / 0.1 | фикс. лот / потолок лота |
| COPIER_MAX_POS / COPIER_MAX_LATENCY_SEC | 6 / 300 | лимит зеркалок / свежесть сделок |
| COPIER_POLL_SEC | 5 | период опроса БД |
| COPIER_MAGIC | 20260828 | magic копира |

**Тест 2026-08-27 (dry-run, демо, локально):** копир увидел 2 открытые сделки
гибрида (GER40.s LONG, NAS100.s LONG), залогировал зеркальные входы с SL/TP,
маппинг записан в copy_trades (виртуальные тикеты −1), last_master_id=126.
Ордера НЕ отправлялись.

**Чек-лист подключения на сервере заказчика:**
1. Windows VPS 2 vCPU / 3-4 ГБ / 40 ГБ + **второй** терминал MT5 в отдельной папке данных (терминал одноэкземплярный на папку!)
2. Перенести проект (git clone private-репо) + .env; счёт подписчика: COPIER_LOGIN/PASSWORD/SERVER
3. COPIER_MT5_PATH → путь ко 2-му терминалу; masters и копир на одной машине — общая bot.db
4. Прогнать ≥1 дня с COPIER_DRY_RUN=1 на сервере: копир видит сделки мастеров, copy_trades наполняется
5. COPIER_MASTER_BALANCE = реальный баланс мастер-счёта (от него считается лот)
6. COPIER_DRY_RUN=0 → `python -m backend.main_copier run`; контроль: `status`, `data/copier.log`
7. Первый день сверять pnl мастер/копия в copy_trades — масштаб лота и проскальзывание в норме

## Известные грабли (важно!)

1. **IPC timeout** (библиотека ↔ терминал): лечится чистой папкой данных + логином в GUI (кэш сервера). После переустановки: `Файл → Открыть счёт → поиск PUPrime`.
2. **«AutoTrading disabled (10027)»**: галка «Разрешить алгоритмическую торговлю» применяется только **на живом сеансе** (Ctrl+O → Советники). После нового старта терминала проверять `trade_allowed`.
3. Терминал **одноэкземплярный** на папку данных; библиотека спавнит свой — перед ручными действиями убивать все terminal64.
4. **Прямые правки `state.json` при живом боте бесполезны** — цикл затрёт. Только через `/start`, `/stop` или при остановленном процессе.
5. У отложенных ордеров MT5 **нет привязки к позиции** (position_id=0) — поэтому только серверные TP.
6. Терминал от MetaQuotes-инсталлера может прийти бетой (6120/6122) — с пакетом 5.0.6090 работает.
7. **Фоновые процессы из Git Bash умирают с сессией** — запускать только через `start_bot.ps1`.
8. Автозамены в коде скриптом с `str.replace` **молча не применяются**, если шаблон не совпал (так три из четырёх заглушек скальп-сигналов не встали) — проверять `grep` после правки.
9. Порт 8080 занят чужим `python -m http.server` — используем 8181.

## ⚠️ Про целевую доходность (проговорено с заказчиком)

Запрос: **8–11%/день**. Честная оценка: **недостижимо** легальной стратегией.
Арифметика на $100 при лоте 0.01: победа ≈ +3%, проигрыш ≈ -2%. Даже при WR 55-60%
реалистичный результат — **1.5–3%/день в среднем, с красными днями**.
Гнаться за 10% можно только увеличением лота → микросчёт превращается в лотерею.

Также: «максимум сделок + максимум прибыли + мини-баланс» — взаимоисключающие требования.
Правильный обход — не частить одним инструментом, а торговать много инструментов
качественной логикой (что и делает мульти-бот).
