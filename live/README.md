## Ключевые решения (и почему так)

### 1. Чистая БД под live — обязательно ДО первой live-сделки
`scalp_trades` не хранит ни счёт, ни режим (проверено: колонки только ticket,
side, entry/sl/tp, времена, pnl, reason, status + добавленные ctx-поля).
Значит live-сделки лягут в ту же таблицу, что 74 демо-сделки гибрида, и на
витрине PnL станет смесью демо и реала — для страницы, которая продаётся как
«проверенная статистика», это неприемлемо.

**Решение:** `split_db.py` копирует текущую `bot.db` в
`data/archive/bot_demo_<дата>.db` (демо-история сохраняется целиком для отчётов),
затем чистит в рабочей БД торговые таблицы (`scalp_trades`, `pairs`, `events`,
`snapshots`, `copy_trades`), оставляя схему. Подписчики Telegram живут в
`telegram.json` — не затрагиваются.

Альтернативу «добавить колонку account/mode и фильтровать» отверг: правок больше
(storage + все *_stats + витрина + Excel), риск выше, а выгода только в том, что
демо и live в одном файле — чего как раз не нужно.

### 2. Риск-база = 150, а не 100
Гибрид считает лимиты позиции и корзины от `HYBRID_TEST_BALANCE` (дефолт 100).
При депозите $150 и базе 100 бот будет осторожнее, чем нужно, а дневной стоп 8%
сработает на $8 вместо $12. Ставим 150.

### 3. Команды Telegram — только владельцу
Сейчас режим открытого доступа: любой написавший боту получает `/stop` и
`/start`. При этом `/stop` вызывает `shutdown_terminal()` →
`taskkill /F /IM terminal64.exe`, то есть убивает ОБЩИЙ терминал, которым
торгует гибрид; `/start` поднимает СЕТКУ на том же счёте (противоречит решению
«на live только гибрид»). На реальных деньгах это недопустимо.

**Решение (`patch_tg_owner.py`):**
- `/status` и `/help` остаются публичными (витрина для подписчиков);
- `/stop` и `/start` — только для `TELEGRAM_OWNER_ID` (chat_id 789368186),
  остальным вежливый отказ;
- `/stop` в live-режиме больше НЕ выключает терминал (только halt + закрытие
  своих позиций) — иначе останавливается и гибрид, и связь с брокером.

### 4. Символы на live проверяем до старта
У реальных счетов суффиксы инструментов часто отличаются от демо
(на демо: `XAUUSD.s`, `NAS100.s`, `GER40.s`). `check_live.py` печатает
фактические имена и риск-таблицу — по ней правим `HYBRID_SYMBOLS`.
Если инструмент не проходит по риску/спреду, он выпадет: на $150 золото,
скорее всего, не пройдёт (на демо при базе $100 уже отсекалось:
`skipped: XAUUSD.s риск 14.7% > 10%`).

## Чек-лист перехода (по шагам)

**Этап 0. Безопасность — ДО live (блокер, не пропускать)**
1. Перевыпустить токен @Dim_forex_bot у @BotFather → новый в `.env` VPS.
2. Перевыпустить GitHub-токен.
3. Удалить GitHub release + тег `vps-data` (внутри `bot.db` с секретами).
4. Сменить пароль Administrator на 185.46.10.179 и root на крипто-VPS.
5. Сменить пароль торгового счёта 29399422 в кабинете PU Prime
   (он проходил через чат).

**Этап 1. Проверка подключения (демо не останавливаем)**
6. На VPS в MT5: Файл → Войти в торговый счёт → 29399422 / PUPrime-Live,
   пароль руками, галочка «Сохранить пароль».
   ⚠️ Один терминал = один счёт: с этого момента демо-торговля гибрида
   прекращается. Демо-историю сохраняем на шаге 8.
7. Запустить `check_live.py` → убедиться: login 29399422, server PUPrime-Live,
   balance ≈ 150, `trade_allowed: True`, есть имена символов и риск-таблица.

**Этап 2. Разделение данных**
8. `split_db.py` → демо-архив в `data/archive/`, рабочая БД пустая.
   Проверить, что архив создан и читается.

**Этап 3. Конфигурация**
9. В `.env` на VPS по образцу `env_live.template`:
   `MT5_LOGIN=29399422`, `MT5_SERVER=PUPrime-Live`, `MT5_PASSWORD=<новый>`,
   `HYBRID_TEST_BALANCE=150`, `TRADING_MODE=real`,
   `HYBRID_SYMBOLS=<фактические имена с шага 7>`,
   `TELEGRAM_OWNER_ID=789368186`.
10. `patch_tg_owner.py` → ограничение команд.

**Этап 4. Старт и наблюдение**
11. Рестарт задач: `fxbot-hybrid`, `fxbot-web`, `fxbot-telegram`
    (терминал не трогаем — он уже залогинен в live).
12. Проверить: сайт показывает «РЕАЛЬНЫЙ СЧЁТ», `/status` пишет «Режим: 🟢 РЕАЛ»,
    в канал уходит `[LIVE]` вместо `[ДЕМО]`.
13. **Первый день — ручной контроль:** первые 2-3 сделки сверить в терминале
    (объём, SL/TP, что magic гибрида), следить за дневным стопом 8% (= $12).

**Этап 5. Копитрейдинг — только после того, как мастер отработает**
14. Второй реальный счёт + второй терминал MT5 в ОТДЕЛЬНОЙ папке данных.
15. `COPIER_*` в `.env`, `COPIER_MASTER_BALANCE=150`, `COPIER_DRY_RUN=1`.
16. Минимум 1 день dry-run → сверить `copy_trades` → `COPIER_DRY_RUN=0`.
